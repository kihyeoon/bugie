## 새 기능

### 초대 코드/링크로 가계부 참여 (BGI-22)

이메일 초대만 있던 것을 **12자 초대 코드** 공유 방식으로 바꿨다.

- **왜**: 애플 로그인 사용자는 이메일이 Private Relay 무작위 주소라 아무도 그 주소를 모른다.
  기존 초대는 `profiles.email` 정확 일치로 상대를 찾았고, 프로덕션 실측 기준
  **애플 계정 25명 중 23명(92%), 전체 37명 중 62%를 초대할 수 없었다**
- 가계부 설정 → 멤버 관리에서 초대 링크 생성, 시스템 공유 시트로 전달
  (카톡·메시지 등 설치된 앱 어디로든)
- 받는 쪽은 **더보기 → 초대 코드 입력** 또는 링크 탭(`bugie://invite?code=…`)으로 참여
- 다회용 링크. 어떤 링크로 누가 들어왔는지 확인 가능, 링크 개별 폐기 가능
- 코드는 혼동 문자(0/O, 1/I/L) 제외 12자, **7일 후 자동 만료**
- 이메일 초대는 보조 수단으로 유지. 프로필 설정에서 **본인 이메일 복사·공유** 추가

설계 문서: `docs/features/ledger-invite/design.md`

## 버그 수정

### 앱이 꺼진 상태에서 초대 링크를 누르면 스플래시에서 멈추던 문제

- 콜드 스타트 딥링크는 `app/invite.tsx`가 **초기 라우트**라 `app/index.tsx`를 거치지 않는다.
  스플래시 자동 숨김은 `_layout.tsx`에서 전역으로 꺼져 있고(`preventAutoHideAsync`),
  실제 `hideAsync()`는 홈·로그인·프로필설정에만 있어서 초대 화면 경로가 비어 있었다
- 로그인 + 프로필 완료 상태에서만 재현됐다. 비로그인이면 로그인 화면이,
  프로필 미설정이면 설정 화면이 스플래시를 대신 숨겨줬기 때문
- 수정: `invite.tsx` / `accept-invite.tsx`에 마운트 시 `hideAsync()` 추가
- 같은 구조의 잠재 문제: **모든 스택 라우트가 `bugie://<route>`로 콜드 진입 가능하고
  전부 같은 행에 걸린다.** 실제로 공유되는 링크는 초대뿐이라 이번엔 두 화면만 고쳤다

## 개선

### 홈에서 날짜를 고르면 그 자리에서 내역을 본다 (BGI-35)

- 거래가 있는 날을 누르면 거래 목록 화면으로 **강제 이동**해서, 그 날에 입력하려면
  뒤로 가기를 한 번 더 거쳐야 했다
- 이제 탭은 선택만 하고, 고른 날의 내역(최대 5건 + "+N건 더 보기")을 홈에서 펼친다
- 목록 진입은 "목록에서 보기" 버튼으로 명시적으로

### 홈이 한 달치를 두 번 받던 문제 (BGI-36)

- 캘린더 집계가 한 달 행을 `select('*')`로 전부 받아 클라이언트에서 합산했고,
  홈이 거래 목록도 함께 쓰면서 같은 달을 두 번 스캔했다
- 일별 합계만 돌려주는 `get_daily_summary` RPC로 대체 (서버 집계)

### 모달 헤더 통일

- 가계부 멤버 관리 모달 4개가 각자 인라인 헤더를 만들어 좌우 슬롯 폭이 달랐고
  (닫기 40px / 스페이서 36px / 아이콘 24px) 제목 위치와 높이가 미묘하게 어긋났다
- `components/shared/ModalHeader.tsx`로 통일 — 제목을 정중앙 고정

## 보안 (앱 코드 변경 없음, DB만)

두 건 모두 **마이그레이션은 이미 프로덕션에 배포됨**. 기록 목적으로만 남긴다.

- **BGI-37** — 비로그인(anon) 상태로 가계부 멤버 조회·초대·소유권 이전이 가능하던 문제.
  `SECURITY DEFINER` 함수의 anon/PUBLIC 실행 권한 회수, 소유권 검사 추가,
  대시보드로 직접 수정돼 코드와 어긋나 있던 함수 5개 정합화, 미사용 함수·테이블 제거
- **BGI-38** — `setup_new_user`/`create_user_profile`에 소유권 검사가 없어
  로그인한 사용자가 **남의 프로필을 덮어쓸 수 있던** 문제. `auth.uid()` 가드 추가

## 마이그레이션

앱보다 **DB가 먼저 배포됐다.** 초대 기능은 새 테이블·RPC가 있어야 동작하고,
구버전 앱은 이들을 호출하지 않아 영향이 없다(inert).

| 마이그레이션 | 내용 | 상태 |
| --- | --- | --- |
| `20260830000001` | `get_daily_summary` RPC (BGI-36) | 배포됨 |
| `20260830000002`~`0010` | DEFINER 함수 권한·소유권 검사 (BGI-37) | 배포됨 |
| `20260830000011` | `setup_new_user` 소유권 검사 (BGI-38) | 배포됨 |
| `20260830000012` | 초대 테이블 3개 + RPC 3개 (BGI-22) | 배포됨 |
| `20260830000013` | 초대 테이블 자동 부여 GRANT 회수 (BGI-22) | 배포됨 |

### 이번에 굳힌 규약

- **읽기 집계 RPC는 `SECURITY INVOKER`(기본값)로 두되, `deleted_at` 필터는 본문에도 넣는다.**
  RLS에만 맡기면 `service_role`/superuser 경로에서 삭제된 거래가 합산돼 조용히 틀린다
- **`RAISE EXCEPTION`은 같은 트랜잭션의 INSERT를 롤백한다.** 실패를 기록해야 하는
  rate limit 같은 로직은 `RAISE` 대신 `RETURN NULL`로. 호출부에서 `data === null`을
  에러로 변환한다 — `if (error) throw`만 쓰면 실패를 성공으로 처리한다
- **새 테이블에는 GRANT를 명시한다.** Supabase 기본 권한이 신규 테이블에 ALL을
  자동 부여한다(2026-10-30 이전 정책). `0013`에서 `alter default privileges`로 차단했다
